# Engineering decisions

1. **One knowledge system, two products.** Evergreen references and dated Korean editions share source/topic IDs. A briefing is not the canonical topic record. Adaptive depth avoids both shallow summaries and an encyclopedia page-count target.
2. **Canonical identities and aliases before new topics.** Existing identities, FTS hits and historical context guide decisions; an attempted Create using a known alias becomes Update. The original technical body is separate from the latest summary. This deliberately preserves useful older explanations.
3. **A small curated starting point, not a category-filling generator.** LLM architecture, RAG, and harness/MCP are useful connected references. They cite real official originals and are labelled editorial notes, not Gemini output. Further topics must earn relevance and depth.
4. **SQLite FTS5 before vectors.** It adds real ranked source retrieval, chunks, citations and reproducible metrics without model downloads or paid infrastructure. Small current evaluation gives perfect topic Hit@1 but only 2/3 document P@1; embeddings are not justified solely by terminology. Better labels and retrieval-error analysis precede a local semantic alternative.
5. **Deterministic research orchestration.** The conditional evidence loop is explicit, bounded and testable. Separate LLM agents would spend free quota and complicate recovery without improving this small workload. Planner/Researcher/Evaluator/Publisher are responsibilities, not invented multi-agent autonomy. Additional retrieval is local, not model-selected arbitrary external browsing.
6. **Explainable scoring, freshness only 5% by default.** Strong personal interests guide but do not whitelist. Credibility and novelty are proxy signals and their limitations are visible. All weights are configurable and validated. Low-priority material remains traceable instead of being deleted.
7. **Strict fail-closed generation.** Exact model standard pricing is verified from Google's official table, including free input and output. Billing-disabled status needs the user's explicit project acknowledgement because an API key cannot prove it. Conservative reservations include failed attempts, usage is recorded, and no model/provider fallback or billing action exists.
8. **Structured output plus independent checks.** JSON schema prevents malformed decisions; Update must reference a retrieved ID. Wiki structure/citation validity and suspicious quantities are checked independently. These checks do not prove semantic entailment; uncertain generated interpretation remains labelled as a draft.
9. **Keep canonical Notion pages; add an index database.** The API cannot safely move the existing ordinary pages into a database. Metadata rows link to canonical bodies, retaining permanent page identities and manual content. The trade-off is one click from searchable metadata to the body. Copying bodies into new pages would split identity.
10. **Owned-block hashes and no blind write retries.** This makes an acknowledged repeated run write-free and protects unknown user content. It cannot guarantee exactly once after a lost write response. We prefer a visible reconciliation step over a duplicate-making retry.
11. **Native Mermaid and tested small Python examples.** Genuine explanatory flows communicate mechanisms without unlicensed figures or paid image hosting. API acceptance/storage is verified; browser rendering was not visually inspected. Trusted curated examples are executed in tests; generated code is never automatically executed.
12. **No paid dependencies or platform imitation.** The project demonstrates ingestion, retrieval, contracts, orchestration, evaluation, integration and monitoring using local/free components. It does not imitate an enterprise platform's interface or claim enterprise operational readiness.
